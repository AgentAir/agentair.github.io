AlmaLinux 9.8をSyslog受信サーバーにする：rsyslog・firewalld・UDP/514の設定

2026-07-12 / Linux / AlmaLinux / rsyslog / Syslog

Home Articles About

はじめに

検証環境で、ネットワーク機器などから送信されるSyslogを受信するため、 AlmaLinux 9.8をSyslog受信サーバーとして設定しました。

最初は、AlmaLinuxにSyslogサーバーとして利用できるソフトウェアが 標準で入っているのか分かっていませんでした。 確認するとrsyslogが導入されていたため、追加製品は使わず、 rsyslogでUDP/514を待ち受ける構成にしました。

この記事では、実際に追加した設定とfirewalldの許可、 rsyslogの再起動、待受け状態の確認方法を整理します。 なお、送信元機器からの実ログ受信結果と保存先については、 確認できた内容を別途追記する予定です。

今回の検証環境

  • OS：AlmaLinux 9.8
  • 用途：Syslog受信サーバー
  • ソフトウェア：rsyslog
  • プロトコル：UDP
  • ポート：514
  • サーバー内FW：firewalld
  • インターネット接続：なし

このAlmaLinux環境はインターネットに接続していません。 追加パッケージが必要になった場合は、インターネットへ接続できる別端末で用意し、 ローカルのファイルサーバー経由で転送する必要があります。 今回はrsyslogが導入済みだったため、追加インストールは行いませんでした。

最初に確認したこと

まず、rsyslogパッケージがインストールされているか確認します。

rpm -q rsyslog

続いて、rsyslogサービスの状態を確認します。

sudo systemctl status rsyslog
sudo systemctl is-active rsyslog

systemctl is-activeの結果がactiveであれば、 rsyslogサービス自体は起動しています。 ただし、サービスが起動しているだけでは、UDP/514を待ち受けているとは限りません。

設定ファイルの場所

rsyslogの主要な設定ファイルは、次の場所にあります。

/etc/rsyslog.conf

追加設定は、/etc/rsyslog.d/配下に 拡張子.confのファイルとして分けて配置できます。 今回は、次のファイルを作成しました。 

/etc/rsyslog.d/remote.conf

標準の/etc/rsyslog.confを直接変更せず、 追加設定を別ファイルにすることで、変更箇所を確認しやすくしました。 検証環境を別の担当者へ引き継ぐ場合にも、追加した設定を説明しやすくなります。

UDP/514でSyslogを受信する設定

/etc/rsyslog.d/remote.confに、次の設定を記載しました。

module(load="imudp")
input(type="imudp" port="514")
  • module(load="imudp")：UDPでSyslogを受信するためのモジュールを読み込む。
  • input(type="imudp" port="514")：UDP/514で受信を待ち受ける。

rsyslogでは、UDP入力にimudpモジュールを使用します。 ポート番号はinput()で指定します。

参考： rsyslog公式ドキュメント：imudp

設定ファイルの構文を確認する

rsyslogを再起動する前に、設定ファイルの構文を確認します。

sudo rsyslogd -N1

エラーが表示された場合は、そのまま再起動せず、 /etc/rsyslog.d/remote.confの記述を確認します。 括弧やダブルクォーテーションの不足、モジュール名のスペル、 設定の重複などが確認ポイントになります。

firewalldでUDP/514を許可する

rsyslog側で受信設定を入れても、firewalldで拒否されている場合は 外部からSyslogを受信できません。 次のコマンドでUDP/514を恒久的に許可しました。 

sudo firewall-cmd --permanent --add-port=514/udp
sudo firewall-cmd --reload

設定後、許可されたポートを確認します。

sudo firewall-cmd --list-ports

514/udpが表示されれば、現在確認しているゾーンに UDP/514の許可設定が入っています。 NICが所属するゾーンも確認しておくと確実です。 

sudo firewall-cmd --get-active-zones
sudo firewall-cmd --zone=public --list-all

参考： Red Hat Enterprise Linux 9：リモートロギングの構成

rsyslogを再起動する

設定を反映するため、rsyslogを再起動します。

sudo systemctl restart rsyslog
sudo systemctl status rsyslog

起動に失敗した場合は、次のコマンドで直近のログを確認します。

sudo journalctl -u rsyslog -n 50 --no-pager

UDP/514の待受け状態を確認する

rsyslogのサービス状態とは別に、OS上でUDP/514を 実際に待ち受けていることを確認します。 

sudo ss -lunp | grep ':514'
  • -l：待受け中のソケットを表示する。
  • -u：UDPソケットを表示する。
  • -n：ポート番号を名前に変換せず表示する。
  • -p：ソケットを使用しているプロセスを表示する。

出力に0.0.0.0:514が含まれていれば、 IPv4の各インターフェースでUDP/514を待ち受けています。 [::]:514はIPv6側の待受けを表します。

受信できない場合の切り分け

Syslogを受信できない場合は、次の順番で確認すると整理しやすいと考えています。

  1. rpm -q rsyslogでrsyslogが導入されているか確認する。
  2. rsyslogd -N1で設定ファイルの構文を確認する。
  3. systemctl status rsyslogでサービス状態を確認する。
  4. ss -lunpでUDP/514の待受け状態を確認する。
  5. firewall-cmdでサーバー内FWを確認する。
  6. 途中のFWやACL、ルーティングを確認する。
  7. 送信元機器の送信先IP、プロトコル、ポートを確認する。
  8. 受信パケットとログ保存先を確認する。

パケットがサーバーまで届いているか確認できる環境では、 次のコマンドも切り分けに利用できます。 

sudo tcpdump -ni any udp port 514

パケットが表示されなければ、送信元設定やネットワーク経路を確認します。 パケットが表示されるのにログファイルへ記録されない場合は、 rsyslogの保存ルールや保存先を確認します。

引継ぎ時に残す情報

今回のサーバーは検証環境ですが、別の担当者が使用する可能性があります。 そのため、Syslogサーバーについては次の情報を残すことにしました。

  • OSとバージョン
  • セグメント、IPアドレス、デフォルトゲートウェイ、DNS
  • SSHなどの接続方法
  • Syslogのプロトコルとポート
  • サーバー内FWとネットワーク上のACL
  • rsyslogの設定ファイル
  • 受信ログの保存先とローテーション設定
  • Syslogを送信している機器
  • インターネットへ接続できないこと
  • 追加パッケージを持ち込む方法

今回追加した主な設定ファイルは /etc/rsyslog.d/remote.confです。

まとめ

AlmaLinux 9.8をSyslog受信サーバーとして使用するため、 rsyslogでUDP/514の受信設定を追加し、firewalldで同ポートを許可しました。

設定の中心は、次の2行です。

module(load="imudp")
input(type="imudp" port="514")

設定後は、rsyslogサービスが起動していることだけでなく、 UDP/514の待受け、firewalld、ネットワーク上のACL、 送信元機器の設定を分けて確認する必要があります。

今回は受信サーバー側の設定までを整理しました。 次は実際の送信元機器からテストログを送り、 保存先とログ形式、ログローテーションの動作を確認したいと思います。
